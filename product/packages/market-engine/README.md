# @hrizzup/market-engine

The maths behind Hrizzup's play-money markets:

- **the yes/no markets** (PLAN.md step 1.7a): a market's price, buying, limit orders, selling, Yes and No cancelling out, fees, and settlement. The ledger (`@hrizzup/ledger`, step 1.7b) runs it inside each trade's database transaction, and the rest of step 1.7 builds on that;
- **the Bitcoin perp** (step 3.4a): a perpetual future in play money, with leverage, liquidation, funding, an opening fee, and winners scaled down when the pool runs short. Its books and calls come next in 3.4a.

It is plain calculation, with no database, network or screens.

The maths is [Manifold's](https://github.com/manifoldmarkets/manifold), copied with its tests and kept close to Manifold's own code, so the two stay easy to compare. Which files to take was settled in [docs/research/round-2-readiness.md](../../../docs/research/round-2-readiness.md) (section C9) and [docs/research/manifold.md](../../../docs/research/manifold.md) (section 1 for the perp).

## What changed from Manifold's code

**In every file, only what our coding rules need:**

- **Imports:** `lodash` becomes `lodash-es` (the same library as ES modules); `common/x` imports become relative paths; every relative import names its `.ts` file; type-only imports are marked `type`. lodash's `Dictionary` type comes from lodash's own types (`@types/lodash`), which `lodash-es`'s types don't carry.
- **Formatting:** Biome's (semicolons, lines up to 100 characters, imports in order).
- **Tests:** each imports `describe`, `expect` and `it` from Vitest, instead of using Jest's globals.

**Beyond that, in Manifold's files:**

- `bet.ts`: the chart helper `calculateMultiBets` is left out (it needs `chart.ts`), and `getNewBetId` returns `crypto.randomUUID()` instead of Manifold's 12-character random id.
- Biome's errors, each fixed without changing what the code does: a few `forEach` callbacks that returned a value now have a block body (`answer-probs.ts`, `calculate-metrics.ts`, `fees.ts`, and four tests); `calculate-metrics.ts` compares answer ids with `(a ?? null) === (b ?? null)`, which is what its `==` did; `number.ts` uses `===` on a length; `calculate.ts` gives one variable its type.
- `calculate-cpmm-arbitrage.ts` keeps Manifold's text exactly, apart from its import lines and one redaction, and Biome skips it (`biome.json`), so it stays easy to compare. The redaction: a commented-out example of a Manifold market carries a Firebase Storage access token (in an image address from Manifold's development site), which our secret check rightly refuses, so the token reads `REDACTED`.
- `perps/amm.ts`: one `forEach` callback that returned a value now has a block body (Biome's error), doing the same thing. Every other perps file and perps test is Manifold's exactly, after the changes every file gets.

## Hrizzup's changes

Our changes to what the maths does (milestone 2), each pinned by a test in [src/changes.test.ts](src/changes.test.ts):

- **The time is passed in.** Buying (`getBinaryCpmmBetInfo`), selling (`getCpmmSellBetInfo`), redeeming (`getRedemptionBets`), the profit figures (`calculateUserMetricsWithoutLoans` and the functions under it) and `tradingAllowed` take the time as their last argument, `now`, in milliseconds since 1970, instead of reading the clock: it stamps the bet and its fills and decides which limit orders have expired, so one trade inside one database transaction uses one time, and tests repeat exactly. The functions those share with Manifold's multi-answer code (`computeFills`, `computeCpmmBet`, `calculateCpmmSale`, `calculateAmountToBuyShares`) take `now` as an optional last argument: the yes/no path always passes it; Manifold's multi-answer code, kept switched off, leaves it out and still reads the clock, as Manifold wrote it. A test makes the clock throw while buying, filling a limit order, selling, redeeming and settling.
- **No loans.** A sale and a redemption always carry a loan of 0; their loan inputs are gone (`getCpmmSellBetInfo` no longer takes `loanPaid`, `getRedemptionBets` no longer takes `loanPayment`), and redeeming and settlement ignore any loan a position might carry (`getLoanPayouts` returns none).
- **Manifold's other features stay switched off:** markets with several answers, numbers, dates and "stonks" are never opened; our slim market type has no second currency, leagues, ranking, bonuses or subsidy pools. Manifold's market-ranking measure (elasticity) is left as it was.
- **No logging:** the two `console.log` calls in the yes/no maths are gone (selling, and the profit figures). Manifold's switched-off multi-answer code keeps its own.
- **The two error messages** in `computeFills` show their numbers: they were in single quotes, so they printed `${betAmount}` literally. The second named `limitProb`, which is declared later in the function, so it now shows the limit price passed in (`initialLimitProb`); a plain template literal would itself have crashed.
- **Fees: one setting, at zero.** `TAKER_FEE_RATE` in `fees.ts` (Manifold's unexported `TAKER_FEE_CONSTANT`, renamed and exported) sets every yes/no trade's fee, `rate × p × (1 − p) × shares`. It stays 0 until the Product chat decides the rate.

The front door no longer offers `computeFills` and `computeCpmmBet`, whose time is optional; buying and selling cover them.

## The perp: Hrizzup's changes and our engine

Milestone 2 of the perp's maths, each part pinned by a test in [src/perp/changes.test.ts](src/perp/changes.test.ts), with the clock throwing throughout.

- **The time is passed in.** Manifold's `openPosition` and `closePosition` (`perps/amm.ts`) take the time as a required `now` instead of defaulting to the clock, and `closePosition`'s share to close has no default either (a required argument can't follow one): pass 1 for all of it. Manifold's tests pass a fixed time (`NOW`); otherwise they are unchanged. `getPerpOpenInterestCapacityForOpen` closes a whole position, which stamps no time, so it passes that position's own time.
- **The settings** ([src/perp/settings.ts](src/perp/settings.ts)): Manifold's defaults, the founder's decision of 10 November 2026, with leverage capped at 10 times (`PERP_LEVERAGE_CAP`). The opening fee is `PERP_TAKER_FEE_BPS_DEFAULT` (10 basis points of the size, under its cap of 100) with no size extra (`PERP_TAKER_FEE_IMPACT_DEFAULT`, 0); funding is hourly (`FUNDING_PERIOD_MS`). What Manifold leaves to whoever creates a perp comes from its own recommendation for its Bitcoin perp (`launch-manifest.ts`): funding sensitivity 1, a yearly funding cap of 100% (so 1/8,760 an hour), prices no older than 2 minutes, and Ṁ25,000 from the house in each pool. Manifold recommends 5 times leverage there; the founder set 10. `assertPerpSettings` refuses anything past the cap or past the bounds Manifold's engine enforces. Every change to them goes in the rule-change log, which comes with the perp's books.
- **The engine** ([src/perp/engine.ts](src/perp/engine.ts)): Manifold's server combines the maths inside each database transaction (`backend/shared/src/perps/engine.ts`, not copied); this is that combination with the database left out, step for step: `openPerpPosition` (a flip first closes the other side; then the fee, the cash check, the exposure cap and solvency), `closePerpPosition` (all or part), `applyPerpPrice` (liquidations, then winners scaled down if the pools run short; if even that leaves them short, the price moves on, nothing else does, and trading pauses until a price applies cleanly) and `applyPerpFunding` (hourly, the crowded side paying the other). Each returns the new book and the play money to move (`PerpMove`: margin and fee into the pools, payouts out), or a refusal with its reason. The ledger writes the moves as double-entry lines.
- **The starting rules** (PLAN.md, "Perps"): leverage above the settings' cap is refused (`leverage_too_high`); an order fills only at a price published after it was placed (`not_next_price`, Manifold's `orders.ts`); the opening fee goes into the trader's own side of the pool, closing is free; the off switch is Manifold's trading mode: closing-only refuses opens, halted refuses closes too, while liquidations and funding always run. A price over 2 minutes old pauses trading.
- **Manifold-only features stay off:** no fee channel for trading by API key (the engine never asks for it), no bans, unique-trader bonuses or events (the books keep their own), none of Manifold's other price feeds. There is no logging in the perps maths.
- **The stand-in price** ([src/perp/stand-in-price.ts](src/perp/stand-in-price.ts)): a new price every 5 seconds, the same for the same seed and moment (on the same Node version, which the repository pins), a random walk of the price's logarithm with Bitcoin's typical volatility (about 55% a year: 0.6% an hour, 3% a day), starting at $100,000 on 1 January 2026. Any moment's price is worked out directly (a Brownian bridge, 24 halvings), in about a microsecond. **The seed is a secret key** (16 hexadecimal digits): this code is public, so every draw is a keyed hash of the seed (HalfSipHash-2-4, written from its specification and checked against its reference test vector), and nobody without the seed can tell a future price. Tests use their own fixed seeds; staging's is kept with its other keys, never in the repository.

## Our money tests

[src/money.test.ts](src/money.test.ts) (milestone 3) checks that play money is never created or lost. A small ledger stands in for 1.7b's engine: it holds every balance, opens a yes/no market with the house's starting amount (Ṁ1,000), and applies what the maths returns for each trade, the way Manifold's server does. After every step it checks that the balances, the fees and the money in the market add up to what there was at the start, that every Yes share and every No share is backed by Ṁ1 in the market, and that no balance goes below zero; after settlement, that the market holds nothing. The clock throws throughout.

They cover a yes/no buy, a limit order (filled in full, partly filled then withdrawn, expired, and stopped when its owner's money runs out), a sale (part, all, and into a resting order), Yes and No cancelling out, and settlement by Yes, by No, at a set probability (MKT) and by cancel, each case under all four settlements; then 40 random markets of 150 trades each and one of 2,000, every one settled.

**What they found:** a cancel pays each trader what they put in less what they took out, so a trader who sold at a profit gets a negative payout: the profit is taken back. Within one market that returns everyone to where they started, but a trader who spent the profit elsewhere would go below zero. The question is in the Product brief.

## Our money tests: the perp

Milestone 3 of the perp's maths proves that no play money is created or lost. A small ledger ([src/perp/test-ledger.ts](src/perp/test-ledger.ts)) stands in for the books: it holds every balance (each trader's, the house's, and the perp's own), opens the perp with the house's subsidy, and applies each step's moves as pairs, out of one account and into another. After every step it checks that the step changed the pools by exactly its own moves, that the perp holds exactly its two pools (Manifold's own `isPerpEscrowBalanced`), that nobody and neither pool is below zero, and that the pools can pay every winner (Manifold's `assertPerpStateSolvent`) unless the book is paused. The clock throws throughout.

- **[src/perp/money.test.ts](src/perp/money.test.ts)**, each case with its amounts worked out by hand: opening (the margin and the 0.1% fee into the trader's own pool); closing at a profit (the margin back from its own pool, the profit from the other side's), at a loss, in parts and in one go, and a flip; hourly funding (the crowded side paying the other, inside the pools), once and for 48 hours; liquidation (the margin staying in the pool, then paying the other side's winner); the pool running short (the winner scaled down to what the pools can pay, and paid exactly that; and, on a book left short as in Manifold's incidents, a winner scaled down to nothing and paid their margin) and the exposure cap refusing what the other side couldn't back; and the 10 times cap refusing more, moving nothing.
- **[src/perp/simulation.test.ts](src/perp/simulation.test.ts)**, the long simulation: 30 traders with Ṁ2,000 each over three weeks of the stand-in price, a new price every 5 seconds (362,880 prices): about one order a minute, each filling at the next price; traders with their own patience (half of them hold for days) and their own taste in leverage, opening, adding, flipping and closing all or part, now and then asking for more than 10 times; funding from an hourly job; six hours closing-only and an hour halted (the off switch), and five minutes without prices across an hour mark; everyone closing at the end. About 370,000 steps, every one checked. A second run gives the pools Ṁ300 a side, so the traders' winnings outgrow them and winners are scaled down, some to nothing. Both are seeded, so every run is the same run, and together they take about 4 seconds.

What happened in them (seeded, so always this on the pinned Node version): 3,750 opens, 2,769 closes, 782 flips, 3 liquidations, 503 fundings (one an hour, both directions; the hour without a fresh price skipped) and 110 orders refused by the off switch in the long run; in the thin one, winners scaled down at 15 prices, two of them to nothing and paid their margin.

**What they found:** asked for every 5 seconds, funding would run every 59 minutes, since Manifold lets a run come up to a minute early to absorb a late scheduler; funding belongs on an hourly job (recorded for the perp's books).

## Type declarations for other packages

Other packages (the ledger, `@hrizzup/ledger`, and through it the website) read this package's types from [types/](types/), not from `src/` (`package.json`, "exports"); the code they run is still `src/`. A package importing TypeScript source checks it again under its own settings, where `noUncheckedIndexedAccess` is on, and Manifold's code fails that (see "Checks"). `types/` is written from `src/index.ts` with this package's own settings (`pnpm --filter @hrizzup/market-engine types`, [scripts/types.ts](scripts/types.ts)), never edited by hand, and `src/types.test.ts` fails when it differs from what the source gives now. Biome skips it, as it skips the agreement's generated types.

## Checks

- **Tests:** `pnpm --filter @hrizzup/market-engine test` (Vitest). Quick checks run them on every pull request, with the type check. They run in two groups, one after the other ([vitest.config.ts](vitest.config.ts)): the unit tests, then the perp's long simulation, whose heavy computing would otherwise take time from Manifold's heaviest fuzz test, which already runs close to its 5-second limit on GitHub's machines (4,981 ms on #92's run).
- **TypeScript:** our shared settings, except `noUncheckedIndexedAccess`, which is off in this package only ([tsconfig.json](tsconfig.json) says why): with it on, about 300 lines of proven maths and tests would need rewriting.
- **Biome:** every file is formatted and linted, with one override for `src/manifold/` (in `biome.json`) that switches off style-only rules for Manifold's code (non-null assertions, `any`, string keys, template strings and the like) and Manifold's own `isNaN` and `isFinite` checks, whose `Number.` versions behave differently for values that aren't numbers. React's and Next.js's rules are off for the whole package, which has no screens.
